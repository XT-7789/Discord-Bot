PURPOSE
=======
This file is the starting point for a maintainer or AI that cannot see the
previous conversation. Read it before changing the project.

The current product goal is simple: a new player should begin a fun activity in
under one minute and always understand the next action. Main Menu now prioritizes
Play -> free Memory Match / Casino -> Collection titles. Economy remains the
Mine -> Craft -> Sell -> Upgrade loop. Warfront is optional. XC and War Credits
are separate currencies.

OWNER PREFERENCES AND NON-NEGOTIABLE RULES
==========================================
1. Speak Chinese with the owner. Keep all player, Admin and Help UI in English.
2. Use the current X SYSTEM visual language: dark Discord panels, cyan accent,
   strong headings, short explanations and obvious primary actions.
3. Design for Discord mobile first. Prefer short native text and real buttons.
4. Help belongs on the Main Menu only. Other panels use Back, Menu and Close.
5. Back must return to the actual previous panel and preserve useful selection.
6. Never require a slash command when a normal panel button can perform or open
   the same action. The Admin panel should expose almost all routine Admin tools.
7. Do not change rewards, prices, odds, cooldowns, VIP/SVIP rights, permissions
   or war balance unless the owner explicitly approves that scope.
8. Do not reset data, modify real player assets, run repairs/backups against
   production, or start a second production Bot.
9. Every completed code or documentation update must be committed and pushed to
   GitHub. Give the owner the commit hash.
10. Offline tests are not mobile visual approval. Ask for a fresh phone screenshot
    after a visual change and label it pending until the screenshot is reviewed.

CURRENT OVERVIEW UI - IMPORTANT
===============================
The /overview panel is implemented in player_overview.py.

Several designs were tested and rejected on an actual phone:
- Pillow image dashboard: text was too small, looked poor and FreeType failed on
  Termux builds without PIL._imagingft.
- Discord code block grid: unwanted code styling and copy icon.
- Normal text fake columns using spaces, vertical bars or dot separators: Discord
  uses a proportional font, so later rows drift even when the first row looks OK.

Do not restore those designs without explicit owner approval.

The current implementation at commit 7ff6770 uses one stable summary line for
each tile:

  WALLET · 1,854 XC · Bank 17,127
  MINES · Energy 92 · Level 2
  PRODUCTION · Ready 0 · Queue 0/7

Each group contains up to three summary lines and is followed immediately by its
matching row of up to three real buttons. Groups are separated by native Discord
horizontal separators. This retains compact three-item groups without pretending
that proportional text can form a real three-column table.

With every section selected, tile order is:
1. Wallet, Mines, Production
2. Market, Nation, Missions
3. Craft, Stocks, VIP

The current phone appearance of commit 7ff6770 is still awaiting a new screenshot.
The screenshot that triggered it showed the older dot-column layout from 60ea641.
Do not call the broad UI goal complete until 7ff6770 or a later design is checked
on the owner's phone.

Overview compatibility details:
- image_options() remains as a compatibility hook and clears obsolete attachments.
- Overview is native text only; it performs no Pillow rendering.
- assets/fonts/Overview.ttf and its licence remain in the repository but are unused.
- test_overview_image.py has a historical filename but now tests text-only output.
- Saved Customize selections, ownership checks and live-state reads must remain.
- Opening, refreshing or navigating the Overview must never settle an asset action.

CURRENT PLAYER EXPERIENCE
=========================
- Main Menu: Play, Economy, Profile and Missions, plus optional Warfront. Help and
  Close appear only at the bottom of this menu.
- Play contains a persistent free Memory Match, Casino link, daily reward allowance
  and Collection progress. casual_games.py owns its schema, settlement and panels.
- Memory rewards default to three games sharing 25 XC (9/8/8). Later games are
  Practice. Four cosmetic titles can be equipped on Profile.
- Panel-launched Casino rounds now use a review step. Blackjack, Coinflip and Slots
  have mobile bet presets; blocked rounds offer Free Game.
- Economy Centre groups Finance, Earn, Market and Casino-related destinations.
- My Overview shows the current goal, next upgrade and selected live summaries.
- Workshop shows recipe count/readiness, a recipe selector and a direct recommended
  recipe. It uses one Back/Menu/Close navigation row.
- Economy journey: mined materials can lead to a matching recipe, crafting can lead
  to system sale, and completed products can lead to valid use/sale actions.
- Resource Pack is the beginner civilian product. It uses the existing item/recipe
  database and must not be made directly purchasable or player-market tradeable.
- Missing pickaxe, missing materials, insufficient balance/energy, full queue and
  empty lists should explain the reason and offer a useful next panel.
- Transaction confirmation must re-check price, balance, inventory, permissions and
  feature switches. Duplicate clicks must never settle twice.

ADMIN AND DASHBOARD
===================
- /admin opens the private X BOT Staff Control Centre in staff_panel.py and
  staff_sections.py. Routine tools should be available through selectors, forms
  and confirmation buttons instead of command typing.
- Discord Admin includes Applications, Tester Reports, Verification, Reward Codes,
  Economy status and maintenance tools. Economy status is read-only there.
- Dashboard is the only editor for Economy settings. Keep its existing Flask app,
  URL, authentication and database. Do not create a second configuration source.
- Dashboard settings must validate explicitly and save atomically. Log operator,
  changed setting and before/after value, excluding credentials and tokens.
- Bot and Dashboard share xwar.db. A successfully saved setting is read on the next
  relevant Bot action unless its field is explicitly documented as restart-only.
- Never weaken the existing role or owner permission policy for UI convenience.

PHONE DEPLOYMENT
================
On the existing Termux checkout:
  git pull --ff-only

Then restart the existing supervised Bot process. Do not launch another Bot token
session. Old Discord messages do not automatically change; open a fresh /overview,
/menu, /economy or /admin panel after restart.

phone_start.sh supervises both python -u dashboard.py and python -u bot.py and writes
logs under logs/. Do not print or commit .env contents. Required secrets include
DISCORD_TOKEN and DASHBOARD_PASSWORD; Dashboard OAuth variables are optional only
where the current code already treats them as optional.
